fix: pipeline stuck at CLASSIFIED when OCR returns empty text + wizard improvements

Root cause of stuck documents:
- OCR node calls vision LLM which fails (400) when provider is misconfigured
- Entity extraction and field extraction both skip processing when ocr_text=""
- Field extraction is the terminal node that sets COMPLETED, but its skip path
  returned without updating document status, leaving documents at CLASSIFIED forever

Fix: field_extraction skip-no-ocr path now sets doc.status="COMPLETED" so
documents always reach a terminal state even when OCR produces no text.

Setup wizard improvements (Setup.tsx):
- Step 2 Ollama: added separate Vision Model for OCR field (leave empty to
  reuse text model — multimodal models like gemma3 work without it)
- Step 2 LiteLLM: added warning banner explaining that the proxy must have the
  provider API key configured independently; clarified that the wizard key is
  only for proxy authentication; added Vision Model field for OCR
- Step 2: added optional collapsible Embedding section (toggle + model name)
  saved as embedding_enabled and embedding_model SystemConfig keys
- StepState extended with ollamaVisionModel, litellmVisionModel,
  embeddingEnabled, embeddingModel fields
- saveConfig now persists ocr_vision_model and embedding settings

Downstream effect: any new upload with a misconfigured LLM will now reach
COMPLETED (with empty text/fields) instead of getting stuck at CLASSIFIED.
